# Codex + Whisper MVP: 상태 점검 및 실행 계획

**22:02 UTC 갱신:** 실제 MK20 관리 연결 및 미들웨어 연결 완료. PC Wi-Fi source `.197` 사용 필요(Ethernet은 PC 측 인터페이스이며 MK20의 인터페이스가 아님). TOP framebuffer 교체 전/후 비교에서 한글 표시 복구 확인. Codex-only MvpController 추가, 39개 테스트 통과, 실제 app-server Korean 응답 통과. 아직 전체 MVP 완료 아님. 최신 실행 방법/변경/미검증 범위와 Codex 이후 Antigravity→OpenCode 순서 및 완료 기준은 [HANDOFF.md](../HANDOFF.md)의 맨 위 인계 섹션이 이 문서의 오래된 현황표보다 우선한다. Codex quota guard(7% 남음)로 구현 중단 및 인계.

작성: 2026-09-13. 현재 코드 및 테스트 기준. QMK 소스 확보와 독립적으로 진행한다.

## 목표와 범위

MK20 마이크 → 로컬 Whisper → 초안 확인 → 사용자의 Send → 지정한 Codex 작업 → 응답 확인.
Codex 앱을 통한 음성 처리 실험은 중단한다. Whisper는 STT이며 TTS 대체 엔진이 아니다. TTS/Speak는 이번 MVP 범위 밖이다.
Codex 실행 연동과 음성 인식을 분리한다. 기존 CLI app-server 연동이 기본이고 Desktop IPC는 `SNOWBALL_DESKTOP_EXPERIMENTAL=1`일 때만 켜지는 실험 기능이다. Desktop에서 열린 작업을 다른 CLI 소유자로 이어받는 동작을 검증된 기능으로 간주하지 않는다.

이번 작업은 첫 번째 안정화 묶음과 전체 상태 감사이다. 전체 MVP 또는 모든 UI의 완성 판정이 아니다.

## 이번에 수정한 사항

- Settings: 독립된 20키 화면과 K17 Close. 일반 세션 키 동작으로 빠지지 않으며 초안은 유지한다. 실제 설정 편집은 아직 제공하지 않는다.
- Files: 처리하지 않은 키가 일반 세션의 녹음/설정/새 작업 명령으로 이어지는 문제 차단. 파일 탐색 구현 자체는 미완성이다.
- Send: 빈 초안에서 비활성. sending/unknown에서는 Send, Talk-replace, Cancel을 비활성화하고 원문을 유지한다. 호스트 입력 처리도 동일한 disabled 상태를 검사한다.
- Talk-replace: 취소가 거부된 전송 중/불확실 초안을 지우지 않는다. 취소된 녹음의 worker-busy 재시도가 녹음을 다시 시작하지 않게 검사한다.
- Desktop 소유 초안: 연결 소실 시 CLI 경로로 자동 전환하지 않는다. 미확인 상태로 보존한다.
- Speak와 구현되지 않은 Other/일반 질문 Submit을 비활성화. 승인 Submit은 선택이 있어야 활성화된다.
- Changes의 K1은 실제 동작에 맞게 Stop 대신 Close로 표시한다.
- Codex New: 선택한 프로젝트 경로에서 생성한다. 비슷한 이름의 형제 폴더 작업이 프로젝트 목록에 섞이지 않게 경계를 검사한다.
- 응답 이벤트의 thread ID를 유지하고 다른 호스트/하네스/작업의 델타가 선택 화면 또는 음성 초안에 섞이지 않게 필터링한다.
- 음성 시작 실패 원인이 즉시 일반 세션 화면으로 덮이는 문제 수정.

## 상태별 감사표

판정은 소스 검토와 자동 테스트 범위다. 실제 패널의 글자 잘림, 가독성, 키 입력 및 라이브 Codex 왕복은 별도 검증해야 한다.

| 상태/화면 | 기대 흐름과 UI | 현재 판정 / 남은 문제 |
|---|---|---|
| 시작·연결 중 | 실제 리소스 로드, 명령 준비 전 비활성 | 예시 프로젝트/세션이 기본값에 남음. 연결 상태 모델과 준비 완료 gating 필요 |
| 연결 실패·재연결 | 오류/재시도 표시, 초안 유지, 자동 Send 금지 | 패널 host timeout 존재. Codex 연결 단절/복구, 요청 timeout 및 재시작 복원 미완성 |
| 프로젝트·세션 없음 | 빈 상태, 적절한 New 안내 | `none` 세션으로 녹음 시작 가능. 예시 리소스 제거 및 대상 사전 검증 필요 |
| 세션 대기 | Talk, 유효한 Send, 실행 상태에 맞는 Stop | 빈 Send 비활성 수정. 실제 실행 중 여부 모델 필요 |
| 프로젝트·세션 선택 | 부모 범위 유지, 목록 탐색, 확정 | 프로젝트 경계/New 수정. 느린 비동기 조회가 이후 선택을 덮는 race, 기억한 ID 영속화 필요 |
| 모델·effort·access 선택 | 적용 가능한 값만 노출, 실제 요청과 일치 | 하드코딩 목록, Access 미적용, Desktop 전송 설정 불일치. capability 기반 표시 필요 |
| 녹음 시작·녹음 중 | 시작 ACK 후 REC, Done→변환, Cancel | 현재 시작 ACK 전에 REC 표시. 시작/종료 경합 및 마이크 실패 전용 상태 필요 |
| Whisper 변환 중 | 대기, Send 차단, Cancel | 기존 초안 lifecycle은 늦은 결과 거부. 실제 마이크/네트워크 중단 검증 필요 |
| 무음·빈 결과 | 전송 불가, 다시 녹음 안내 | 전송 차단 존재. 빈 결과 전용 안내 미완성 |
| 인식 실패 | 오류 보존, 재시도 | 시작 오류 덮어쓰기 수정. 녹음 재사용/품질 비교는 후속 |
| 초안 검토 | 대상 고정, 스크롤, 명시적 Send | 대상 스냅샷 존재. 자유 편집/undo 미구현. Talk-replace는 기존 초안을 폐기함 |
| 전송 중 | 원문 보존, 중복 Send·교체 금지 | 버튼/입력 보호 수정. 요청 timeout과 상태 영속화 필요 |
| 전송 미확인 | 원문 보존, 자동 재전송 금지 | UI 보호 수정. 실제 작업 확인 후 해소하는 reconciliation 동작 미구현 |
| 전송 ACK | 접수와 실행 완료 구분 | ACK 문구 존재. 이후 실행 상태/완료/실패 이벤트 통합 필요 |
| 실행·응답 스트리밍 | 해당 작업만 표시, 초안/모달 보존 | thread 필터 수정. 토큰 조각 합치기와 비활성 화면의 이벤트 보관 필요 |
| 완료·실패·중단 | 확정 이벤트로 상태 변경 | 별도 상태 모델 부족. 현재 Stop 문구가 실제 중단 확인 전에 성공을 단정함: 다음 단계 P0 |
| 승인 요청 | 원래 request/session에 바인딩, ACK 후 해소 | 선택 없는 Submit 차단. request ID 타입 보존, 최신 스키마 응답 값 대조, 다중 요청 큐, ACK/error 처리 필요 |
| 일반 질문·Other | 질문 ID별 답변, 다중 질문/페이지 처리 | 미지원 Submit/Other/Speak 비활성. 일반 질문 응답 구현은 미완성 |
| 질문 Later·Stop | 보류 복귀 가능, Stop은 실제 중단 | Later 재진입 경로 없음. 질문 Stop이 화면만 닫음. P0로 수정 필요 |
| Files | 실제 파일 목록, Up/열기, 독립 모달 | 키 fallthrough 차단. 예시 목록이며 실제 파일 열기/Up 미구현 |
| Changes | 파일 선택/페이지, 스크롤, Close | K1 표시 수정. 늦은 diff 조회가 닫힌 모달에 반영되는 race와 긴 경로 표시 검증 필요 |
| Settings | 독립 모달, 닫으면 기존 초안 복귀 | 최소 정보 화면 구현. 설정 저장 UI는 후속 |
| 양쪽 노브 | 좌: 현재 화면 탐색, 우: 음량/음소거 | 세션/Files 스크롤 테스트 존재. 질문 탐색 미구현, 우측은 수치 변경이며 실제 재생 제어 아님 |

## 단계별 방향과 완료 기준

### 1. 상태 모델과 Codex 실행 경로 안정화 — 다음 구현 우선순위

먼저 입력 dispatcher를 테스트 가능한 controller로 분리하고 가짜 Codex/Whisper/transport로 이벤트 순서를 재현한다. 현재 `index.ts` 안의 handler는 UI 단위 테스트에서 직접 실행되지 않는다는 한계를 해소한다.
연결/작업/음성/모달 상태를 구분하고 표시와 가능한 명령을 한 기준에서 계산한다. 예시 세션 제거, 빈 상태, 느린 조회, 선택 변경, 중복 입력을 처리한다.
Stop은 요청/접수/중단 확인을 구분하고 실패를 표시한다. 소유자 변경 금지와 작업별 이벤트/요청 timeout을 테스트한다.

완료 기준: 오프라인 및 빈 세션에서 잘못된 요청 0회, 중복 Send 1회 이하, 잘못된 작업으로 전송 0회, Stop 실패를 성공으로 표시하지 않음. Codex 프로토콜은 설치된 버전/스키마에 대조한다.

### 2. Whisper 초안 흐름 완성

시작 ACK, 무음, 실패, 취소, 다시 녹음, 편집/undo, 전송 결과 미확인 해소를 같은 화면 규칙에 맞춘다. 현재 로컬 base 모델을 기준으로 한국어·영어·코드 용어 fixture를 마련하고 다른 모델 선택은 측정 후 결정한다.

완료 기준: 취소 후 늦은 텍스트가 복귀하지 않음, 전송 전 수정 내용 유지, 오류가 초안으로 전송되지 않음, 인식 완료만으로 Codex 턴이 시작되지 않음. 인식 품질과 stop-to-draft 지연을 별도 기록한다.

### 3. 승인·질문 및 보조 화면 정합성

승인 ID/소유 작업/상태를 고정하고 여러 요청, Later/복귀, 거절, ACK 실패를 처리한다. 일반 질문은 질문별 텍스트/선택 답변으로 전달한다. 설정은 실제 적용 가능한 항목만 제공한다. Files는 실제 읽기 전용 탐색으로 연결하거나 MVP에서 준비 중으로 명확히 비활성화한다.

완료 기준: 화면의 활성 키 모두 실제 동작과 일치, 미지원 항목은 비활성, 모달 종료 후 초안·선택·스크롤 복원, 오래된 질문 응답 차단.

### 4. QMK 없는 통합 리허설

가짜 입력/UDP fixture로 전체 상태를 반복하고, 실행 코드가 생성한 UI 상태를 패널 또는 동일 상태 기반 미리보기에서 검토한다. 기존 `docs/simulator`는 별도 예시 상태를 사용하므로 현재 middleware 검증 증거로 혼동하지 않는다.
사용 가능한 USB host 연결에서 MK20 녹음·Whisper·패널 표시를 검증한다. Codex 테스트용 작업에서만 실제 명시적 Send/Stop/승인을 검증한다.

완료 기준: 상태별 재현 절차·스크린샷·로그·테스트 결과를 연결한 acceptance report. 단위 테스트, fixture 음성, 실제 마이크, 실제 Codex 결과를 구분한다.

### 5. QMK 소스 수령 후

보드/MCU/복구 이미지 일치 확인 → 독립 전원 입력 동작 검증 → 키/노브 회귀 검증. 소스 수령 전에는 추정 suspend 원인을 확정하거나 펌웨어를 수정하지 않는다. 다중 하네스/공유 GPU/호스트 discovery 확장은 Codex MVP 이후다.

## 검증과 제약

- 변경 전 `npm test --prefix host`: 24/24 통과. Whisper fixture 기반 인식 포함, 실제 마이크 입력 아님.
- 추가 회귀 테스트: Settings/음성 단계별 키 상태/20키 중복/질문 비활성/프로젝트 범위/New 경로/stream thread ID.
- `npm test --prefix host`는 TypeScript 빌드도 실행한다. 최종 결과는 HANDOFF.md에 기록한다.
- 테스트는 실제 Codex 프롬프트를 보내거나 펌웨어를 플래시하지 않는다.
- 기존 작업 트리가 광범위하게 수정/미추적 상태였다. 이번 수정과 기존 작업을 묶어 임의 커밋하지 않는다.
- 현재 프로토타입을 보안 pairing 또는 배포 가능한 제품으로 판정하지 않는다. 개발용 UDP/ADB와 실행 호스트 API의 접근 범위는 제품화 전 별도 정리한다.
