# ADR 002 — Durable commands, decisions and recovery

Status: implemented and verified for MW.02.01.01.02, 2026-09-17.

## Answers to the previous handoff

1. Idempotency identity is **host-local commandId alone**. The retained immutable request fingerprint includes authenticated actor/controller, exact Session key, owner incarnation, operation, payload, expected session revision and decision reference/revision. Same ID + same normalized request returns the existing record, including unknown/terminal state. Same ID + changed request is an idempotency conflict. Authorization is checked by the calling boundary before accessing another actor's record; ID knowledge is not a credential. Revision is compared only on first admission; a byte-equivalent retry does not become stale merely because the original succeeded. Core return type is authoritative; future HTTP will project it without inventing success from 202.
2. Decision state is central, not the per-controller presentation cache. Persisted pending decisions become needs_review on restart. A read-only, same-owner proof must confirm the exact native request and native revision is still pending. Never infer validity from text. Wall-clock expiry is a fail-closed local upper bound; expiry never means approve or deny. If the native harness says expired/resolved, that is authoritative. If a resolution may already have been sent, keep the claim and mark unknown; no second decision command until correlated read-only evidence resolves it.
3. The durable journal is authoritative for what Snowball intended/sent, not for what the external harness actually did. Same-owner read-only probes can supply a correlation receipt/native decision state. Startup itself never calls a plugin, starts a process, logs in, sends or automatically retries. Missing response, missing transcript or phrase matching is not proof of non-delivery. A queued command at restart becomes cancelled-before-dispatch; a dispatched/acknowledged command becomes unknown. Payload remains in history for a new explicitly initiated command, never an automatic replay.
4. Default per-session active queue bound: 32; host-wide active bound: 1024. Reject new admissions at the bound and preserve older commands. Pending commands are ordered within a session. At most one dispatch/unknown delivery barrier per session; a reliable ACK releases the delivery barrier without waiting for a whole model turn, so cancel/decision responses can follow an acknowledged send. Device event buffers are ephemeral, separate from this command store, and stale events are dropped before admission. Queue overflow never deletes a durable command.

## Persistence choice and safety boundary

Use a small single-writer append-only journal, bounded transactions, monotonic sequence and SHA-256 chain, with fsync before publishing each transition. Keep no external database/native module dependency in this tranche. Record dispatched BEFORE invoking an adapter. Persist decision claim + command admission in the SAME record so two controllers cannot answer twice. Dispatch is explicit and owner-bound; cancellation/throw/timeout after entering the adapter is unknown unless a trusted adapter reports an authoritative not-sent receipt.

Journal open uses an exclusive lock file; no automatic stale-lock stealing or PID assumptions. A process crash leaves the lock. Recovery tooling must make an explicit operator-confirmed offline takeover (only after checking the old process is stopped); no network/API endpoint for takeover is introduced. This conservative availability tradeoff prevents split writers. Corruption, incomplete records or future schema versions fail closed without silently dropping bytes. An initialized v1 journal is required; older controller-state snapshots are independent and are not silently converted into delivery evidence. No implicit migration of unknown schemas.

The MVP enforces a file-size cap instead of unlimited growth. Retention/compaction is a future maintenance task; at capacity fail before dispatch, never prune idempotency history implicitly. User-data directory/OS ACL enforcement belongs to the local installer/storage boundary. File mode requests 0600 on platforms that support it; this is not a Windows ACL implementation. Local fsync durability and directory sync are tested as process-crash recovery; sudden power-loss guarantees on every OS/filesystem are not claimed. No LAN or shared filesystem journal is supported.

## Ownership and integration boundary

Session ownership includes a stable Session key plus a current owner incarnation supplied by a trusted adapter. Reconnecting a pipe or selecting a UI item cannot transfer ownership. Owner changes invalidate queued commands and make uncertain deliveries block that Session until proven outcomes are recorded. Unknown old-owner actions cannot be reconciled with a new-owner guess. Registration/read proof methods are internal capabilities, not arbitrary public JSON operations.

ControllerContext approval/draft bindings are display caches, not execution authorization. Presentation-local resolve methods must never call a harness directly. CommandJournal is the central compare-and-set authority. Registered sessions are unverified on restart and must be re-observed before new admission/dispatch. Native request IDs are represented as string OR safe integer (including 0), with type preserved. Local decision revision is separate from native revision and advances on every validity/claim transition.

No true end-to-end exactly-once guarantee is possible without provider idempotency/correlation. This design promises deduplicated admission and no blind retries. Adapter integration and real-provider proof remain future tasks; simulated proof in tests is not live-harness acceptance.

An acknowledged receipt means the owner accepted this exact operation, not merely that bytes reached a socket. For decision resolution it must mean the owner accepted the answer; otherwise the adapter must retain uncertainty. A recorded correlation/ACK cannot later become not-delivered, including after restart. Recovery and owner changes use bounded per-command transactions; an interrupted recovery is safe to resume without executing any adapter. This also allows a full queue of maximum-sized payloads to recover within the 1 MiB transaction bound.
