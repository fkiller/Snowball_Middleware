## Findings and changes

1. **Corrected finding — local noAuth is intended policy, not a vulnerability.** The user explicitly requested PIN-free local Web access. The earlier removal was an audit error and has been reversed. Normal runtime uses noAuth while retaining loopback-only bind, Host/Origin checks and bounded controller contexts. Token mode remains opt-in. Device pairing is separate. Regression: security-audit and local-runtime tests.
2. **High — remote self-enrollment.** packages/core/src/lan-host.ts returned the PIN from unauthenticated /peer/pair/initiate and accepted the same caller's key through /verify. Both HTTP pairing routes now reject, and external-interface binding fails closed. Added replay rejection, bounded listener and peer wait. This is containment, not a finished LAN pairing protocol; plaintext responses, persistent trust, mutual authentication and a local approval ceremony still need design/real tests.
3. **High — untrusted hardware bypassed command admission.** The pre-existing lab launcher connected unsigned MK20 UDP input directly to private Codex Desktop IPC, bypassing owner binding and durable command admission. The launcher now stops before touching state/devices. Its working code is preserved for extraction. Use npm run start:local; do not restore this launcher as production control.
4. **High — provider events crossed ownership boundaries.** SessionService accepted arbitrary provider session keys, retained old listeners and allowed queued dispatch/interrupt/decision after disable. Added current-adapter/host/provider checks, owner checks, listener disposal, disabled-operation guards and detached returned snapshots. Discovery cannot grant ownership. Multi-instance registration still needs design: the adapter map is keyed by plugin ID, not full instance ID.
5. **High — fabricated control and unsafe HTML.** Supervisor invented projects, sessions and successful agent replies, inferred project ownership from substring matches, and interpolated device/provider/transcript strings into HTML. Removed fake data/actions/results and fuzzy joins; dynamic values use text nodes. Empty state is explicit. Actual session/project IDs and draft behavior still require UI integration/acceptance. Queue admission is never displayed as provider completion.
6. **High — incompatible OpenCode control protocol.** Existing fixture accepted Bearer auth, text-only send, a fabricated decision endpoint and Codex-shaped SSE. Official OpenCode server documentation uses Basic auth, parts-based messages, different approval routes and provider events. Corrected local Basic-auth health/read access, disabled redirects, bounded/validated session responses and unverified control; 401 is not connected. A real Windows 1.18.31 server/observer was checked read-only, but no safe ownership/exact-decision contract has been proven.
7. **Medium — transcript traversal/resource exposure.** Antigravity read/watch accepted arbitrary path components and whole unbounded files. Added identifier, realpath containment and 4 MiB checks. Observer remains read-only; filesystem snapshots are not an official stable control API. Same-user concurrent filesystem races and rotation/partial-line fidelity remain limits.
8. **Medium — tests contacted personal hardware and depended on a sibling repo.** Normal tests opened HID and sent to hardcoded private IPs. Hardware tests now require explicit flags; MK20 IPs must be supplied. Hardware-only imports are deferred. HID report mapping was enabled from enumeration/open evidence without a completed button gesture or macOS capture; production profile list is empty until reviewed evidence exists.
9. **Medium — distribution and evidence integrity.** The middleware source now has a separate private Git remote; packages remain private/UNLICENSED. Codex, OpenCode and Antigravity harnesses have separate private repositories, tagged prereleases, downloaded asset hash checks and Windows/macOS fresh-package-install CI; see `PLUGIN_DEVELOPMENT.md`. MK20 remains in Snowball_Control, and independently reviewed device-plugin releases, public licensing, desktop signing and macOS desktop acceptance remain open. The protocol reference and static package boundary checks still do not amount to a hostile-code OS sandbox.

## What is solid enough to retain

The versioned plugin host has bounded framing/pending requests, digest approval and process crash isolation. Core avoids provider/device imports. The durable journal, composite identities, explicit context destinations, loopback Host/Origin checks and workspace read boundaries have meaningful regression coverage. They should be integrated rather than replaced. Plugin processes have the current user's OS privileges; manifest permissions are disclosures and entrypoint hashing does not authenticate the full package or publisher.
